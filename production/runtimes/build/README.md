# production/runtimes/build/

**The build runtime — what every other runtime is built with.** `symonlearn` activates it;
these are its verbs. Every wrapper here is GENERATED by `scripts/generate-build-runtime.py`
from one table; it resolves its target inside the portal that owns it and reads
`SYMON_REPO` rather than guessing where it is.

## Interconnects

```
symonlearn (root) ........... exports SYMON_REPO, SYMON_OUT; puts bin/ on PATH
  -> bin/symon* .............. one verb each; OE verbs export OEROOT/BITBAKEDIR
     -> upstream/build/ ....... the PINNED bitbake + openembedded-core the OE verbs run
        -> ENDS: upstream is read, never written
     -> work/tools/ ........... the estate's own tools, by the same wrappers
        -> work/pins/ .......... symonscan/symondeps write it; symonlock checks it -> ENDS
     -> work/output/<rt>/ ..... symonbake builds into it; symonprove reads the image from it
        -> production/<area>/ .. the proof output -> ENDS: evidence is read, never adapted
```

## Verbs

| Verb | Does | Lineage |
|---|---|---|
| `symonbake` | bitbake, one runtime's build dir, background priority | estate |
| `symonbuild` | every runtime, in parallel, per-run logs | estate |
| `symonclosure` | the Python dependency gate, from wheel METADATA | estate |
| `symondepends` | the dependency graph as dot | OE / bitbake |
| `symondeps` | re-derive dependencies, licences, vendored code into work/pins | estate |
| `symondeterm` | two scanner runs, byte-identical, or it is not a control plane | estate |
| `symondev` | modify, add, upgrade a recipe in a workspace | OE / bitbake |
| `symondiffsigs` | why did a task re-run? diff its signature | OE / bitbake |
| `symondocs` | one README per folder, interconnects first, no dead ends | scripts/ |
| `symonemulate` | boot an image under qemu | OE / bitbake |
| `symonfacts` | host truth: driver, GPU, listeners, disk | estate |
| `symongetvar` | one variable's value as bitbake sees it | OE / bitbake |
| `symonguard` | is a cooker live? never edit a recipe while one is | estate |
| `symonhash` | every production/ SHA256SUMS still matches its files | estate |
| `symonhistory` | has this failed before? | estate |
| `symonlayers` | show, add, remove layers in a build dir | OE / bitbake |
| `symonlinkage` | native linkage audit: who defines what, no RUNPATH into a build | estate |
| `symonlock` | does disk agree with the lock, and the lock with the report | estate |
| `symonmap` | the API map: every route, C symbol, function, from the source | scripts/ |
| `symonnative` | run a native-sysroot binary | OE / bitbake |
| `symonnice` | renice every live bitbake to background priority | estate |
| `symonpin` | clone at a commit, move .git to .gitpins, commit the files at their pin | estate |
| `symonpkgdata` | what package owns a file; what a package ships | OE / bitbake |
| `symonprove` | extract the image, run under the target loader, host cache inhibited, report every library mapped | estate |
| `symonrecipe` | create a recipe from a source tree | OE / bitbake |
| `symonreport` | acquisition-state.md and the phase board from work/pins | scripts/ |
| `symonscan` | re-derive pins and submodules from the pin stores into work/pins | estate |
| `symonselftest` | OE's own selftest against this layer | OE / bitbake |
| `symonsstate` | which tasks would come from sstate | OE / bitbake |
| `symontest` | every test suite in the estate, discovered not listed | estate |
| `symontoolset` | this: regenerate production/runtimes/build/bin from the table | scripts/ |
| `symonverify` | HEAD:<path> tree_sha == the lock, every submodule gitlink too | estate |

`symonbake` is the one hand-kept file here: it is the launcher itself, the thing the
wrappers hand off to. `estate_processes.py` is its cooker-visibility check.
