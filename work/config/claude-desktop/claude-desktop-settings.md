### Why discovery must be on, and the model list empty

Read from the installed app bundle (`/usr/lib/claude-desktop/resources/app.asar`,
version 2.2553.0), not from documentation:

```js
Wo  = ["sonnet","opus","haiku","fable","mythos"]
Ko  = /^(sonnet|opus|haiku|fable|mythos)(-[\d.]+)?$/
Mxe = ["claude", ...Wo, "anthropic"]
Nxe = /...|gpt|...|openai|.../          // hard blocklist
qo(id) = Nxe.test(id) ? false : Ko.test(id) || Mxe.some(m => id.includes(m))
// a /v1/models row survives iff  qo(row.id) || row.anthropic_family_tier in Wo
```

Consequences:

1. A model named `gpt-oss-20b` can **never** be offered. `gpt` and `openai` are both
   blocklist entries.
2. `symon-chat` trips no blocklist entry but matches no allow-pattern either, so it
   survives **only** because the gateway emits `anthropic_family_tier`.
3. Typed entries in the Models list go through a separate validator that drops
   anything it judges "not an Anthropic model". That path cannot carry the tier
   field, so typing `symon-chat` there is the one way to make this fail.

So: discovery ON, Models list EMPTY, and the gateway supplies the tier.

`anthropic_family_tier` is a wire field, not a claim of equivalence. It is also what
sets `ANTHROPIC_DEFAULT_<TIER>_MODEL` for Code sessions the app spawns.

| Setting | Set to | Why |
|---|---|---|
| SSH connection engine | **system-openssh** | The built-in library ignores `~/.ssh/config`, your keys and your agent. Your sshd is on a non-default port, and only your ssh config supplies it. |
| SSH client program | `/usr/bin/ssh` | MEASURED. The placeholder `/opt/openssh/bin/ssh` does not exist here. |
| SSH host allowlist | `symon` once the host entry below exists; add `*` only if you want any host | Empty/unset means the feature is off. |

**This host has no `symon` ssh entry yet, so a Code session over SSH to it cannot
connect.** To add one, run in your own terminal:

```sh
cat >> ~/.ssh/config <<'EOF'

Host symon
    HostName 127.0.0.1
    Port 22222
    User google
    IdentityFile ~/.ssh/id_ed25519
EOF
chmod 600 ~/.ssh/config

# authorise your own key for loopback sessions (public half only)
install -d -m 700 ~/.ssh
touch ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
grep -qxF "$(cat ~/.ssh/id_ed25519.pub)" ~/.ssh/authorized_keys \
  || cat ~/.ssh/id_ed25519.pub >> ~/.ssh/authorized_keys

ssh -o BatchMode=yes symon 'echo SSH OK; hostname'   # must print SSH OK
```

Do not set the allowlist until that last command prints `SSH OK`. An allowlist
entry for a host you cannot reach looks like a configuration problem later.

## Key

One command, run in your own terminal or pasted here with a `!` prefix. It prints no
secret, only a fingerprint, and puts the key on your clipboard:

```sh
mkdir -p -m 700 ~/.config/symoneural && (umask 077; openssl rand -hex 32 | tr -d '\n' > ~/.config/symoneural/gateway-9001.key) && chmod 600 ~/.config/symoneural/gateway-9001.key && wl-copy < ~/.config/symoneural/gateway-9001.key && echo "created + copied to clipboard; fingerprint $(sha256sum ~/.config/symoneural/gateway-9001.key | cut -c1-16)"
```

The gateway reads that exact file and accepts the value as either
`Authorization: Bearer <key>` or `x-api-key: <key>`.

## Order of operations

1. Paste the key into the window.
2. Leave the Models list empty and Model discovery ON.
3. Wait until the gateway is up on 9001 and `curl` proves it. **Test before Apply.**
   A saved configuration is not evidence; a passed Test is.
4. Apply only after Test passes.
